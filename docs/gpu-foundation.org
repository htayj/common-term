#+title: Common Lisp GPU renderer

* Selection and dependencies
Use =bin/common-term --renderer auto|gpu|cpu= independently of
=--backend auto|x11|wayland=. The default =auto= requests hardware first.
It selects CPU only for initialization unavailability after successful cleanup.
An explicit =gpu= request propagates unavailability; cleanup errors propagate
in either mode. Renderer choice does not change explicit backend selection.

The internal =lispterm/gpu= system and =common-term.gpu= package contain the renderer,
CFFI driver bindings, shader generation and pure atlas/instance models.
The display system depends on GPU, not the reverse. Loading the system creates
no context. Renderer, bindings, shaders and GPU tests are Common Lisp;
existing shell/Nix files provide launch, dependency and verification glue.

* Context and ownership
=open-context &key software device= creates an offscreen OpenGL ES 3 context
through EGL and GBM. Hardware selection checks the EGL device's association
with the opened DRM render node and rejects =EGL_MESA_device_software=.
=context-info= returns driver, EGL, device and runtime metadata. Explicit
=:software t= is for the software-control test, not normal hardware selection.

Create, use and close contexts and renderers on their owner thread in their
creating process. =assert-context-owner= checks both identities and binds the
context. Driver calls mask supported SBCL floating-point traps and protect
native calls against asynchronous interruption. Close the renderer before
=close-context=. Checked cleanup retains handles needed for retry.

The SBCL save hook refuses a heap with live GPU contexts. The host lifecycle
quiesces the window owner and destroys graphical resources before checkpoint
fork; reopening constructs fresh resources from logical session state.

* Composition
The display layer supplies raw glyph masks and resolved foreground/background
colors. The bounded R8 atlas stores binary masks, keyed by copied
grapheme/bold/span values. =atlas-begin-frame= protects the new frame's glyphs
before eviction. Slot epochs invalidate stale instance mappings; successful
uploads acknowledge pending atlas changes.

Each packed instance is 32 bytes: eight little-endian unsigned 32-bit words
for column, row, atlas slot, flags, foreground, background, span and line code.
Flags represent bold, underline and hidden text; line codes cover single,
double-width and the two double-height halves. Lisp shader ASTs from
=shader-form= are emitted by =emit-shader= as transient GLSL ES 3 strings.
Instanced triangles sample masks and compose into an RGBA8 framebuffer.
Overlapping wide cells retain uncovered fragments through scissored draws.
Dirty atlas and instance ranges determine uploads.

* Renderer interface
- =make-renderer :context :width :height :cell-width :cell-height= creates a
  renderer using positive logical pixel sizes. The caller owns the context.
- =renderer-resize renderer width height cell-width cell-height= changes sizes.
- =renderer-write-cell renderer column row= accepts =:glyph-key :mask
  :foreground :background :bold :underline :hidden :span :line-size=.
  Colors are resolved =#xRRGGBB=; span is 1 or 2. Line sizes are =:single=,
  =:double-width=, =:double-height-top= and =:double-height-bottom=.
- =renderer-draw= uploads dirty data and executes pending GPU composition.
- =renderer-readback= draws pending state and returns top-left-origin,
  row-major unsigned 32-bit =#xAARRGGBB= pixels for presentation or capture.
- =renderer-copy-target renderer target-fbo width height &key invert-y=
  copies the rendered image entirely on the GPU to a distinct complete caller
  framebuffer of matching dimensions. It can reverse destination Y and restores
  read/draw framebuffer bindings and scissor state.
- =renderer-metrics= returns operation and transfer counters.
  =renderer-close= releases renderer resources before the caller closes context.

* Presentation
Hardware composition and window-buffer transport are separate choices.
X11 transfers GPU-readback pixels using PutImage. Wayland supports the
GPU-readback path through shared-memory buffers. Capture requests also use
readback; the display caches it until the next pending frame change.

The public Wayland presentation path exports dedicated EGLImage targets when
linux-dmabuf capabilities permit import of their plane descriptors, formats and
modifiers. Lisp Unix transport passes the file descriptors. Targets receive
GPU copies with vertical inversion and checked completion, and remain reserved
until compositor release. Unsupported capabilities use GPU-readback SHM.
=gpu-wayland-dmabuf= verifies public presentation with zero readbacks, exact
compositor pixels, release/reuse, resize, reopen and checked close/retry.

A headless Sway fixture using pixman can display pixels composed by common-term's
hardware GPU. That compositor choice is not proof of direct GPU buffer import.
Direct-buffer verification requires a capable GLES compositor fixture.

* Verification
Run from the repository root after =scripts/bootstrap-deps --tests=.
GPU checks use the pinned =scripts/sbcl= runtime. For example:

#+begin_src sh
tests/verify.sh gpu-probe
tests/verify.sh gpu-software-control
tests/verify.sh gpu-shader
tests/verify.sh gpu-atlas
tests/verify.sh gpu-first-frame
tests/verify.sh gpu-offscreen
tests/verify.sh gpu-evidence
tests/verify.sh gpu-x11
tests/verify.sh gpu-wayland
tests/verify.sh gpu-lifecycle
tests/verify.sh gpu-wayland-dmabuf
tests/verify.sh gpu-language
#+end_src

=gpu-probe= checks real device-associated hardware and a draw/readback.
=gpu-software-control= draws on an explicitly selected software device and
checks hardware-policy rejection. First-frame/offscreen checks compare GPU
pixels with the CPU reference. Evidence checks inspect actual uploads/draws
and a shader negative control. Native gates use private displays; fixtures
must not attach applications to inherited desktop endpoints.

The Lisp test registry rejects unknown names, missing checks, errors and
non-T results. =gpu-language= checks migration source types and the limited
shell/Nix glue allowlist. =gpu-preservation= checks the original main-tree
snapshot; =gpu-delivery= additionally requires final signed/integrated revision
and authenticated independent-review evidence. These delivery receipts are
separate from individual renderer checks.
