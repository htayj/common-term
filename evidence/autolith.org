#+title: Actual Autolith inside Lispterm acceptance

* Reproduction

Run =tests/autolith-gate.sh x11=, =tests/autolith-gate.sh wayland=, and
=tests/checkpoint-gate.sh=. These use the pinned installed Autolith 0.67.0
runtime, isolated HOME/XDG trees and private displays, with stdin =/dev/null=.
They call actual Autolith MAIN in the launcher's SBCL main thread. Autolith
is not a subprocess of another Lispterm Lisp image.

Final combined execution: =be6f89cb-eabe-4502-bccd-f824c0da445f=, exit 0.
Logs: =.build/autolith/reconcile-x11-command.log=,
=.build/autolith/reconcile-wayland-command.log=, and
=.build/autolith/reconcile-checkpoint-final.log=.
Structured records are retained under =.build/autolith/{x11,wayland}/=.

The probe enters Lisp into the actual terminal prompt, redefines the cell
renderer to use green foreground, observes calls to the replacement, reopens
the window and captures the modified output. The replacement exists only in
these disposable heaps; it is not a private self.commit journal entry.
The active-image command handler opens a separate shell and receives actual
PTY output. The primary process descriptors and Lisp stream objects are
checked before and after that command.

* Runtime and checkpoint validation

The actual installed backend validation/resume callbacks and TOOL registry
passed 20 assertions: shared registration, two live hosts, close/join/resume,
later-tool failure rollback, partial owner failure rollback, retained failed
rollback tokens and retry, hosted-main refusal before terminal disruption,
and actual forked saver detach/prune followed by usable parent shell input.
Hosted graphical saved-core restoration is unavailable and explicitly refused
before fork. Source-backed launch/reload is supported; private replay journal
and graphical saved-core restoration are not claimed.
