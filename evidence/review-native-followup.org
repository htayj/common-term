* Reproduced failures after repair
- HIGH keymap SIGBUS: xkb-from-fd now bounds size to 2..16777216 and copies with pread into private temporary storage. There is no file-backed mmap in this path. Empty memfd advertised as 8193 and short backing storage now signal typed transport errors, close the FD and never reach the instrumented native parser. A real ftruncate between two partial preads likewise fails safely. Native parser reads owned memory, so subsequent file truncation cannot produce the original mapped-page SIGBUS.
- Keymap FD leak: exact eight-byte payload validation precedes wire-fd-pop. The suite checks malformed lengths 0/1/4/7/9 and FD cleanup. An additional independent empty-payload probe inspected ownership BEFORE wire-close: typed error, original FD still in wire-fds and F_GETFD successful; after wire-close F_GETFD returned -1. Unsupported format consumes and closes its FD.
- X11 false cleanup completion: backend-close propagates the identical stream CLOSE condition and clears backend-state only after normal return. The 39-check suite exercised failures before and after real descriptor closure. State/client/stream/window/GC stay reachable, display remains unusable with cleanup pending, nonowner retry is rejected, owner retry finishes cleanup, descriptor becomes EBADF, and subsequent close is idempotent. Shared tests also exercised timeout, retained partial-open cleanup and blocked reopen.

XKB's 54 checks additionally cover invalid sizes, missing/embedded NUL, invalid UTF-8, invalid XKB syntax, EINTR plus partial reads, actual valid keymap parsing and A input, native pointer teardown and exact FD baseline. Unsafe inputs are rejected before the instrumented native parser; intentionally invalid syntax reaches it and prints the expected libxkbcommon diagnostic. A separate independent injected pread EIO check verified typed error, zero parser calls and FD closure. No corruption warning, fatal signal or process failure occurred.
