* Reproduction and evidence layout

Run =tests/verify.sh vttest-x11= and then =tests/verify.sh vttest-wayland=.
Set =LISPTERM_VTTEST_FILTER= to a case-label substring for a smaller run,
for example =reports-dsr=, =keyboard=, =bug-d=, or =screen=.
The recorder serializes its GUI runs with =.build/vttest-gui.lock=.
The native fixture holds a task-owned virtual keyboard open so that separate
wtype calls do not remove and recreate the seat's sole keyboard capability.

Each run has a new ignored =.build/evidence/vttest-BACKEND.XXXXXX/= directory:
- =NNN-case-pauseNN.png= is a real import/grim capture, with corresponding
  =.grid.txt= and =.status.sexp=.
- =case.transcript.raw= contains bytes actually read from the PTY.
- =case.input.raw= contains only prefixes actually accepted by PTY writes,
  including driver input and terminal replies, in their actual order.
- =case.vttest.log= is upstream's own log; =case.process.txt= records TTY fds
  and initial stty dimensions; =case.exit= records a normal vttest exit.
- =case.result.sexp= records menu completion, host state, and error ring.
  =case.failure.sexp= records an unfinished recorder operation.
- =native-keys.txt= records attempted native injections. With
  =LISPTERM_VTTEST_TRACE_KEYBOARD=1=, =native-events.sexp= records Wayland
  keyboard event boundaries and normalized injected keys.
- =provenance.sha256= protects captures, grids and raw streams.
  New runs also retain the harness source and hashes.

* Concrete minimal repros and fix batches

1. Engine safety and cursor margins first. On a fresh24x80 screen feed octets
   =27 91 49 50 59 49 51 114 27 91 49 59 49 72 27 77 83=:
   =ESC[12;13r ESC[1;1H ESC M S=. Cursor becomes(-1,0); S indexes-80.
   Bytewise replay of the captured menu2 transcript first errors at offset7452.
   See =.build/evidence/vttest-analysis78/engine-replay.sexp=.
   Inspect =cursor-ri= and directional movement outside the scrolling region;
   test cursor bounds and region scrolling before rerunning menu2.
2. Small renderer correction: =draw-cells= in =src/display/framebuffer.lisp=
   uses =EQUALP= on cell structures. EQUALP treats E/e as equal, so case-only
   updates are skipped. Capture001's grid and PNG disagree accordingly.
   Use an explicit case-sensitive cell comparison, with a focused pixel test.
3. Engine parser/reports: execute C0 controls without abandoning CSI; make
   TBC parameters 1 and 2 no-ops instead of clearing the current stop; add
   British designation and DECREQTPARM. Rerun 005, 008, 014, 023 with
   deterministic byte-level regression checks.
4. Renderer/adapter rendition: expose reverse-screen, line size and blink;
   implement actual double-size geometry, half-width logical row bounds and
   temporal rendition. Rerun menu2 after batch1, then4 and9.8. Engine and
   renderer owners must agree on line-size semantics before parallel edits.
5. Geometry: implement a coherent DECCOLM resize/clear path through engine,
   host and both backends. Extend the baseline recorder's fixed640-pixel native
   crop when native windows can actually become132 columns.
6. VT52 plus input: parser states, addressing, graphics and identify response;
   retain keypad identity through X11/XKB normalization and encode numeric vs
   application modes (ANSI and VT52). Rerun7,5.4,5.5 on both native backends.

A secondary native-input observation is outside the VT100 byte protocol:
removing the headless seat's sole virtual keyboard between wtype invocations
left later key events absent. The continuous keyboard fixture avoids this.
The trace in =vttest-wayland.mDsHMJ/native-events.sexp= shows first Up reaching
the client and then focus leave; the cause of missing later events is not yet
established. Do not mistake those incomplete trials for keypad conformance.

** Modes and offline checks

Use =LISPTERM_VTTEST_MODE=record= (the default) for baseline measurement.
A recorded blocked case is evidence, not a conformance verdict; recording may
finish with an incomplete completed-case inventory. Infrastructure errors,
empty selections and the total watchdog still return nonzero.

Use =LISPTERM_VTTEST_MODE=accept= with =tests/verify.sh vttest-x11= or
=vttest-wayland= for fail-closed mechanical checks. A nonempty filtered selection
is required. Expected, attempted and completed labels must agree. Reject host
errors, unexpected/stale prompts, phase deadlines, loop exhaustion, missing
captures, premature menu returns, nonzero/missing child exit markers, pending
input, and a PTY that has not reached both exited and hangup. The fixed inventory
contains 20 selected paths per backend, not every VT100 submenu. The other
submenus retain their untested status; success for a filtered selection does
not establish full-suite coverage.

Run =tests/verify.sh vttest-check measure ARTIFACT-DIR...= offline to reproduce
legacy byte measurements. Run =vttest-check accept ARTIFACT-DIR...= for strict
v2 validation. Legacy evidence has no interleaved phase events and cannot be
accepted retrospectively. The new event stream records monotonic sequence/time,
both wire directions with octet offsets and exact bytes, enqueue origins,
actual accepted partial writes, driver intent, native-key brackets, captures
and phase boundaries. Validate the entire stream against the two raw files;
check exact query/reply inventory, order, phase, deadline, bytes and counts.
Startup DA is distinct from the requested DA test. Check every injected key
individually in ANSI normal/application and VT52 normal/application phases.

The DECREQTPARM contract is the explicit virtual profile verified against the
VT100 User Guide, chapter 3, DECREQTPARM/DECREPTPARM parameter table:
=https://vt100.net/docs/vt100-ug/chapter3.html#DECREQTPARM=.
Default/0 requires =ESC[2;1;1;112;112;1;0x=; 1 requires
=ESC[3;1;1;112;112;1;0x=. Code 112 means 9600 baud, parity1 means no parity,
bits1 means eight bits, clock1 means multiplier16, and flags0 is the virtual
STP setting. These are virtual terminal settings, not measured physical-line
speeds. The terminal has no SET-UP mode and sends no unsolicited setup reports.
The retained source is in =.build/evidence/vttest-repairs83/engine/=.

** Capture, ownership and provenance

Identify source-written per-pause captions and the exact source-defined pause,
keyboard and navigation inventories. Require fresh output after each advance;
a generic menu prompt in an unrelated submenu cannot complete a case.
Before capture, require a session frame after the final PTY read. Native capture
additionally waits for the compositor frame callback acknowledging a commit
containing that read. This is not presentation-time instrumentation. Preserve
the target output offset, before/after frame counts and native acknowledgement.

Allocate Xvfb with =-displayfd=; use a unique exact window title on that private
server and reject ambiguous matches or a conflicting PID. On native Wayland,
require the exact title and recorder PID in the private Sway tree. Derive the
actual capture rectangle after every resize. Compare the logical grid and PNG
size with the most recent DECCOLM request, not only with one another; a terminal
that ignores 132-column mode must fail. The fixture font is pinned at 8x16.
X11 received keycode, mapping levels, raw modifiers and normalized key are
traced inside the disposable recorder. The core Mod2 bit is recorded without
assuming its NumLock interpretation. Native keypad identity attribution awaits
the later scheduled GUI/input review; injection intent alone is insufficient.

The total watchdog defaults to 1800 seconds. Track only descendants of newly
launched fixture roots, retaining each PID's start token. Cleanup sends bounded
TERM then KILL only when that identity still matches. Native helper startup is
bounded; verify its private config before adopting its compositor PID. Remove
its private runtime directory only after owned processes stop. Retain cleanup
outcomes and owned process metadata. No existing peer is signalled.

Acceptance requires the reviewed pinned Nix vttest binary, including its exact
SHA256; a different VTTEST override is rejected before any display starts.
Record the binary/font identities, pinned dependency definition, effective
command, filter/mode, source files, current Git HEAD/status/diff, fixture
configuration, status/results/exits, window trees/geometry, wire events, images
and cleanup. Hash all generated metadata as well as PNG/grid/raw files after
cleanup. A record-mode binary override is identified explicitly in fixture
metadata; it is not accepted merely because its version string matches.

** Offline verification and limits

and disposable process-tree checks. Logs are in
=.build/evidence/vttest-harness85/=. The analyzer reproduces DSR5, both CPRs,

It establishes that the checker can accept a complete internally consistent
fixture; it is not a Lispterm capture. Negative fixtures cover empty/broken
inventories, wrong/missing/duplicate replies, input-origin spoofing, offset and
phase/time corruption, missing/nonzero exits, nonexited PTYs, loop exhaustion,
and missing/wrong-sized captures. Boundary fakes establish timeout/stale-prompt,
wrong-menu and render-ack failure handling without opening a GUI. The owned-tree
fixture establishes TERM/KILL escalation, watchdog expiry and survival of an
unowned/stale-token negative control created by the test itself.

expected case, matching result filenames, source-defined per-phase query counts,
