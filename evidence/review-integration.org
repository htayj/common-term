* HIGH: PTY backpressure silently truncates host input
Locations: =src/session.lisp:20-22=, =src/host.lisp:96-102=;
related device replies =src/session.lisp:39-48= and events =:60-80=.

=pty-write= returns the accepted prefix length after a bounded write. The
session wrapper retains no unwritten suffix. =send-input= discards that count
and returns HOST, so callers receive apparent success after incomplete delivery.
Paste, text, keys and device replies use the same session helper.

Reproduction used existing fake-display methods from =tests/host-tests.lisp=,
but a real PTY and real spawned child. Open a host with:

#+begin_src lisp
(lispterm:open :backend :x11
  :argv '("sh" "-c" "stty raw -echo; printf READY; sleep 30"))
#+end_src

Wait for READY in the screen. Wrap =lispterm.pty:pty-write= in the disposable
image to record and return the original function's return value, without
changing its arguments. Then call =send-input= with 65536 octets, value 65.
Observed: requested 65536, accepted 13824, returned HOST, error ring NIL.
After an additional 0.2 seconds there was still exactly one write call.
The other 51712 bytes have no retained owner-side queue and cannot be retried.
The wrapper was restored and the host closed/reaped in unwind-protect.

Repair: preserve unwritten suffixes in a bounded owner-managed output queue,

rather than report full success or silently drop bytes. Test genuine partial
writes followed by resumed reading, exact byte order, and overflow behavior.

* MEDIUM: new shell can escape runtime checkpoint ownership
Location: =src/autolith-adapter.lisp:145-148=, with =adopt-host:26-34=.

=graphical-shell= opens the host before adopting it. Host creation and runtime
adoption do not share a lifecycle critical section. If runtime close completes
between those operations, adoption signals because the runtime is quiesced,
but the new host remains registered, attached, and running. The runtime reports
successful quiescence without tracking that live owner or its descriptors.
No cleanup handler closes the newly opened host after adoption failure.

Deterministic interleaving reproduction in the actual packaged Autolith runtime:
- Load =lispterm/autolith= and existing fake-display methods.
- Bind a fresh =lispterm.autolith:*runtime*= and create an actual TOOL registry.
- Temporarily replace =application-tool-registry= to return that registry for
  the disposable call, avoiding construction of a primary application UI.
- Wrap =lispterm.autolith::host-call= so that after its original :OPEN returns,
  call actual =autolith::tool-runtime-close= on the registered runtime owner,
  then return the host to =graphical-shell=.
- Invoke =graphical-shell= with backend :X11 and a real sleeping shell child.

Observed adoption error: "Cannot adopt a host while runtime is :QUIESCED".
Runtime status: (:STATE :QUIESCED :HOSTS 0 :CHECKPOINT-SUPPORTED-P T).
Created host status: :ATTACHED, :WORKER-ALIVE-P T, :PROCESS-STATE :RUNNING,
:ERROR-COUNT 0. This injects the exact lifecycle interleaving, not a claim that
a particular terminal UI event naturally scheduled it during this test.
Original functions were restored and the leaked host explicitly closed/reaped.

the lifecycle lock. Close any unadopted host if creation/adoption fails. Avoid
recursively acquiring the same runtime mutex through the public adoption API.
Test the explicit close-versus-open interleaving and retained-host cleanup.
