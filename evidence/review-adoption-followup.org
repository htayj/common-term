* Mechanism inspection
=open-owned-host= checks RUNNING and increments OPENINGS under the runtime mutex
before invoking the host factory. Factory invocation is outside that mutex.
The original reentrant gap can therefore call runtime-status and TOOL close
without recursively acquiring an already held runtime mutex. TOOL close checks
OPENINGS before changing hosts, state, or rollback tokens and signals the typed
runtime-opening condition. Publication and reservation decrement execute together
under the runtime mutex in unwind-protect. A subsequent close cannot observe a
released reservation without the returned host already being registered.

Interrupts are disabled around reservation/publication, locally permitted during
the factory. The publication region contains no external callback or subsequent
state-check failure. A host-error handler captures the partial-open recovery
handle before unwinding; the original condition is not replaced. Ordinary factory
failure and nonlocal exit release the reservation. Existing close/resume callbacks
still use their existing lifecycle locking; the new factory path introduces no
callback-under-runtime-lock dependency.
